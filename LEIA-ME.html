36WAYS Gestão

Instalação da app num site vosso, com base de dados no Supabase. Faz-se uma vez e demora 20 a 30 minutos. Os dois serviços são gratuitos.

O que está nesta pasta
app/ é o site: a app, o ícone e a biblioteca do Supabase.
1-instalar.sql cria a base de dados e as regras de acesso.
2-importar-dados.sql traz todos os vossos dados atuais: 55 produtos, 55 despesas, 16 vendas, o evento de outubro e a configuração.

1 · Criar a base de dados (Supabase)

  1. Vai a supabase.com, cria conta e carrega em New project.
  2. Nome: 36ways. Escolhe uma região na Europa e uma password para a base de dados. Guarda essa password, mas a app não precisa dela.
  3. Espera um minuto até o projeto ficar pronto.

2 · Instalar as tabelas e importar os dados

  1. Abre o ficheiro 1-instalar.sql num editor de texto (o Bloco de Notas serve).
  2. Troca os três emails de exemplo pelos emails reais dos três sócios, em minúsculas. Só estes emails vão conseguir entrar.
  3. No Supabase, vai a SQL Editor → New query. Cola o conteúdo todo e carrega em Run. Deve aparecer "Success".
  4. Abre uma nova query, cola o conteúdo de 2-importar-dados.sql e carrega em Run.
  5. Para confirmar, abre Table Editor → tabela docs. Devem estar lá 128 linhas.

3 · Criar as contas dos três

  1. Vai a Authentication → Users → Add user → Create new user.
  2. Põe o email (o mesmo que meteste no passo 2) e uma password, e marca Auto Confirm User. Repete para os três.
  3. Em Authentication, nas definições de início de sessão, desliga Allow new users to sign up. Assim ninguém consegue criar conta sozinho.
Se alguém se esquecer da password, mudas-lha aqui em Users.

4 · Ligar a app à base de dados

  1. No Supabase, abre Project Settings → API Keys (ou API).
  2. Copia o Project URL, do tipo https://xxxx.supabase.co. Se não aparecer nessa página, está em Project Settings → Data API.
  3. Copia a chave pública: a Publishable key (começa por sb_publishable_) ou, nos projetos mais antigos, a anon public.
  4. Abre app/index.html no Bloco de Notas. Perto da linha 218, cola os dois valores no lugar de COLOCA_AQUI_… e grava o ficheiro.
Nunca uses a secret key nem a service_role. Essas dão acesso total à base de dados. A chave pública pode estar no site sem problema, porque os dados estão protegidos pelas regras do passo 2: sem uma conta de sócio não se vê nada.

5 · Pôr o site online (GitHub Pages)

  1. Cria conta em github.com e carrega em New repository. Nome: 36ways-gestao, tipo Public (o GitHub Pages grátis exige que seja público; os dados continuam protegidos).
  2. No repositório, carrega em Add file → Upload files e arrasta o conteúdo da pasta app/: index.html, manifest.webmanifest, os ícones e a pasta lib. Depois carrega em Commit changes.
  3. Vai a Settings → Pages. Em Source escolhe Deploy from a branch, depois main e / (root), e carrega em Save.
  4. Em 1 a 2 minutos o site fica em https://O-TEU-UTILIZADOR.github.io/36ways-gestao/.
Há uma alternativa mais rápida: em app.netlify.com/drop arrastas a pasta app inteira e recebes logo um endereço. Cria conta no Netlify para o site não expirar.

6 · Pôr no telemóvel

  1. iPhone: abre o endereço no Safari, carrega em Partilhar → Adicionar ao ecrã principal.
  2. Android: abre no Chrome, menu ⋮ → Adicionar ao ecrã inicial (ou Instalar app).

Aparece com o ícone da 36WAYS e abre em ecrã inteiro. Cada um entra uma vez com o seu email e a sua password, e fica com a sessão iniciada.

Manutenção

  • Atualizar a app: no GitHub, faz upload do novo index.html por cima do antigo. Os dados ficam no Supabase e não são afetados.
  • Cópia de segurança: em Table Editor → docs → Export to CSV. Façam isto uma vez por mês.
  • Plano grátis: o Supabase pausa projetos gratuitos que fiquem cerca de uma semana sem uso. Se acontecer, entra no Supabase e carrega em Restore. Os dados não se perdem.
  • Novo sócio: acrescenta o email com insert into public.membros (email) values ('email@exemplo.com'); no SQL Editor e cria-lhe a conta como no passo 3.
